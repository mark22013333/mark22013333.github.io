sshm

macOS 上的 SSH 機器管理 TUI。

按 Enter 在目前的 terminal 原地連線；在 Orca 裡按 Shift+Enter 會開新分頁連線。另外可以管理 SSH 轉送（Tunnel 頁）、把機器開通給 AI agent 用專用金鑰連線，並在「關於」頁一鍵更新到最新版。

安裝 GitHub

需求：macOS（Apple Silicon 或 Intel）

// 功能

連線、轉送、更新在同一個 TUI，匯入一行指令

按 Tab 在「機器」→「Tunnel」→「關於」三頁之間輪流切換。

01 · 搜尋打字就過濾

開啟後游標就在搜尋框，直接打字即可過濾，比對名稱、host、user、群組（不分大小寫）。

  • sshm acme 開清單並預填搜尋字
  • Enter 在目前的 terminal 原地連線
  • Esc 清空搜尋，再按一次離開
sshm — 搜尋「db」

02 · Tunnel 頁管理 SSH 轉送

管理 SSH 轉送（-L／-R／-D）。每列顯示狀態燈、名稱、機器名稱與規則摘要（例 L 13306→127.0.0.1:3306、D 1080）。

  • ● 執行中、○ 已停止、◌ 無法確認
  • Enter 啟動／停止，Ctrl+G 前往分頁
  • 啟動與停止需要在 Orca 的 terminal 中執行；其他終端機裡 Tunnel 頁為唯讀
sshm — Tunnel

03 · 從 iTerm2 匯入舊的連線設定一次搬過來

iTerm2 若是用 login.exp <port> <user> <host> <password> 登入，sshm import-iterm 一次匯入。

  • 先進預覽畫面：預設全選
  • 已有相同 host＋port＋user 的標「重複」、預設不勾
  • 讀取過程不寫任何暫存檔
sshm import-iterm

04 · 關於頁與更新在 TUI 裡按 U 更新

「關於」頁列出目前版本、GitHub 上的最新版本、檔案位置與快捷鍵一覽。有新版時，機器頁的狀態列會提示到「關於」按 U 更新。

  • SHA-256 相符才解出 sshm：只能確認下載過程沒有損壞或被截斷，無法防止 Release 本身或 GitHub 帳號被竄改；目前沒有簽章驗證
  • 下載中斷、校驗不符或任何一步失敗，原執行檔都不會被改動
  • 一天最多查一次，查詢失敗不會顯示任何訊息
  • 開發版、執行檔目錄沒有寫入權限、或不是 macOS 時不自動更新，「關於」頁會改列手動做法
sshm — 關於

// 給 AI agent 使用

讓 agent 連進 VM，正常使用時不碰密碼

讓別的 AI agent（Claude Code、Codex 等）能連進 VM 查東西，而且正常使用時不需要、也不會接觸密碼：sshm 用已存的密碼登入一次，替每台機器裝上一把專用金鑰並寫好 ssh 別名，之後 agent 只用 ssh <別名> 連線。

在 TUI 的機器清單選一台按 Ctrl+O 也能開通，已開通的再按一次是停用。這和安裝步驟 3 在 zsh 提示列上叫出 sshm 的 Ctrl+O 是不同功能。

安全界線：這個功能防的是 agent「誤開通」與「順手拿密碼來用」，不是防惡意繞過。agent 與 sshm 在同一個 OS 帳號下執行，技術上讀得到 hosts.json 裡的明碼密碼與 ~/.ssh/sshm/ 的私鑰。要防惡意的 agent，得讓它跑在另一個 OS 帳號、容器或 VM 裡，讀不到你的家目錄。

$ sshm agent enable 範例客戶-PROD-VM   # 開通（列出要做的事，按 y 才執行）
$ sshm agent list                      # 已開通的機器
$ sshm agent list --json               # 給 agent 讀的格式（不含密碼）
$ sshm agent disable 範例客戶-PROD-VM  # 停用（按 y 才執行）
$ sshm agent guide                     # 印出給 agent 指引檔的說明

# 之後 agent 只需要：
$ ssh sshm-prod-vm '<指令>'

// 安裝

一行 curl 裝好

需求：macOS（Apple Silicon 或 Intel）。密碼登入會用到 macOS 內建的 /usr/bin/expect 與 ssh，不用另外安裝。

# 1. 安裝（一行，自動判斷 Apple Silicon／Intel）
mkdir -p ~/.local/bin && curl -fsSL "https://github.com/mark22013333/sshm/releases/latest/download/sshm_darwin_$(uname -m | sed s/x86_64/amd64/).tar.gz" | tar xz -C ~/.local/bin sshm

# 2. 把安裝目錄加進 PATH，並讓行首帶空白的指令不進 history
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
echo 'setopt HIST_IGNORE_SPACE' >> ~/.zshrc

# 3. （選用）在 zsh 提示列按 Ctrl+O 叫出 sshm
sshm zsh-widget >> ~/.zshrc

# 4. 重新載入
source ~/.zshrc
  • 確認版本：sshm --version。升級可在 TUI 的「關於」頁按 U，或重跑步驟 1。
  • 請用上面的 curl 安裝。若改用瀏覽器下載壓縮檔，macOS 會因執行檔未經 Apple 簽章而擋下，需要先執行 xattr -d com.apple.quarantine sshm。
  • 已安裝 Go 1.24 以上的話，也可以用 go install github.com/mark22013333/sshm@latest（裝到 ~/go/bin）。

加入機器（三種方式擇一）

  • sshm add 逐台新增。
  • iTerm2 用 login.exp 登入的，sshm import-iterm 一次匯入。
  • 由別人匯出清單給你：對方執行 sshm export sshm-share.json（預設不含密碼），你執行 sshm import sshm-share.json，再於編輯畫面補上自己的密碼。分享清單時請不要加 --with-passwords，匯出檔中的密碼是明碼。
sshm add

必填：名稱、host、user；Ctrl+S 儲存、Esc 取消。

// 已知限制

使用前請先知道（完整 8 條）

  • 密碼以明碼保存存在 hosts.json 裡。連線時經環境變數交給 expect 腳本，不出現在行程參數中；但 expect 行程的初始環境在連線期間仍含密碼，同一使用者或 root 讀得到。在 Orca 開新分頁時，orca terminal create --command=… 行程存活的短暫期間，其參數仍含密碼。
  • 在 Orca 開新分頁時，密碼會出現在畫面上連線指令（含密碼）是打進新分頁 shell 的文字，會顯示在新分頁畫面與 scrollback 裡。
  • 沒開 HIST_IGNORE_SPACE 時，連線指令會進 history連線指令（含密碼）會寫進 shell history；分頁若是 bash，要另外設定 HISTCONTROL=ignorespace。
  • Orca 可能把 scrollback 存到磁碟依 Orca 原始碼推論，未實測；密碼可能因此留在磁碟上。
  • AI agent 的金鑰沒有 passphrase任何能讀 ~/.ssh/sshm/ 的程式都能用它登入已開通的機器，請只開通需要的機器，用完就停用。
  • 金鑰已登入後仍可能送出密碼（機率極低）若已用金鑰登入，而遠端在登入時窗（20 秒）內、你按任何鍵之前，印出指名本次 user@host 的密碼提示，sshm 仍會送出密碼。
  • 密碼不能含 emoji 等非 BMP 字元macOS 內建的 expect 是 Tcl 8.5，非 BMP 字元會被重複編碼，導致密碼錯誤。中文等 BMP 字元正常。
  • 新分頁的 shell 要是 POSIX 相容的 shell連線指令用 POSIX 單引號規則跳脫；fish 對單引號內的 \ 解讀不同，密碼或參數含 \、' 時可能出錯。
