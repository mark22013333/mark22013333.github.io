ChatPulse

Google Chat 的摘要與 Mention 收件匣，用你本人的身分讀寫。

查閱自己加入的 Space、產出結構化 Summary，並在被人 @ 時取得一份可修改的 Draft Reply。讀寫 Google Chat 一律使用你本人的 OAuth 憑證，不註冊 Chat App、不用機器人身分發話。儀表板與 CLI 的送出動作都需要二次確認；MCP 入口的送出由 Claude 端的工具權限把關。

安裝 GitHub

需求：Python 3.12（引導會自動建立環境）、Google OAuth 的 client_secret.json；摘要與 Draft Reply 另需本機登入的 Claude Code，或 Gemini API key

// 功能

摘要、收件匣、草稿，同一個儀表板

執行 ./chatpulse.sh web 後開啟 http://localhost:8000，在畫面上選「匯入既有憑證」或「使用 Google 登入」。

01 · 單群摘要三種風格，章節結構各不相同

選一個 Space、抓最近 N 則（1~1000，預設 50），Summary 以 SSE 逐字串流產出。三種風格（通用／技術細節／只要待辦）輸出的章節結構不同，不是同一份 prompt 多加一句「寫技術一點」。

  • 技術細節風格多出「已排除的假設與排查過程」，讓接手的人不必重做白工
  • Action Items 從摘要抓出來變成可勾選清單，可複製為 Markdown
  • 推播回 Chat 以你本人身分送出，需要二次確認
  • Summary 只屬於產生它的人，其他 Viewer 看不到
ChatPulse — 歷史 Summary

02 · Mention 收件匣跨所有 Space 找出誰 @ 了你

背景採集器逐群輪詢（預設每 45 秒一輪），把 @ 你的訊息收進收件匣，分成待處理與已處理兩種狀態。

  • 資料庫只存識別資訊（哪個 Space、誰、什麼時候），訊息內容每次顯示時才向 Google Chat 取
  • 在 Chat 被編輯或刪除的訊息，不會顯示過期內容
  • 點一則就能在右側直接產生 Draft Reply
ChatPulse — Mention 收件匣

03 · Draft Reply先寫脈絡分析，再給建議回話

針對一則 @ 產生草稿，串流輸出「脈絡分析」與「建議回話」兩段。改完後以你本人的身分回到原討論串。

  • 可勾選 1~N 個 Reference Space 補充脈絡，預設一個都不勾
  • 脈絡分析一定要寫「脈絡涵蓋」：實際看到哪個範圍、有沒有缺口
  • 參考專案：登錄本機 git repo 並指定哪個分支是正式、哪個是 UAT，草稿就能引用實際程式碼，並標明是哪個環境的哪個 commit
  • 草稿與產生當下的證據（脈絡範圍、參考來源、生成與回話設定）一起存下來，重新整理或隔天再開都讀得回，畫面會標明是先前存的草稿
ChatPulse — Draft Reply

04 · 回覆設定語氣、Persona、提示詞、潤稿

產草稿前可以逐次選這四項，全部選填，一個都不選就跟這個功能不存在時完全一樣。四項都只影響〈建議回話〉，〈脈絡分析〉不受影響；也可以在設定頁存成預設值。

  • Reply Tone：8 種語氣（自然直接、專業正式、工程師協作、委婉柔和…與自訂），和摘要的三種風格是不同的東西
  • Persona：一組個人寫作風格，不是角色扮演，回話永遠以你本人的身分送出。從公開 GitHub repo 匯入時會釘住當下的 commit SHA，原文先淨化、只有結構化的風格資訊會進 prompt
  • Sepia 潤稿：讓回話讀起來不像機器寫的，預設關閉。只做最小幅度修訂，改壞事實會被擋下並退回未潤稿的版本
ChatPulse — 設定

// 第二個入口

在 Claude 對話裡直接用

Web 儀表板與 MCP server 是同一套後端能力的兩個入口，不是替代關係。MCP 入口能列 Space、抓訊息、產生摘要、發送訊息；Mention 收件匣與 Draft Reply 只在儀表板。

MCP 的送出沒有 ChatPulse 這一層的確認：send_chat_message（以及 summarize_chat_space 帶推播參數時）只在工具說明裡請模型先向你確認，實際攔不攔取決於 Claude 端的工具權限設定。

也可以從命令列摘要單一 Space。不加 --post 就不會推播，加了也會再要求一次確認。

# 註冊 MCP 入口（或 ./chatpulse.sh mcp）
$ ./scripts/install-claude.sh

# MCP 工具
# list_chat_spaces / fetch_chat_messages
# summarize_chat_space / send_chat_message
# list_ai_providers

# 最近 50 則，只在終端輸出
$ ./scripts/run_summary.sh "示範頻道"
$ ./scripts/run_summary.sh "示範頻道" 100 --style technical
# 推播回群組，會再確認一次
$ ./scripts/run_summary.sh "示範頻道" 50 --post

// AI 供應商

預設用本機的 Claude Code

摘要與 Draft Reply 的 AI 供應商可以切換，預設 claude（目前解析為本機 Claude Code CLI，吃現有訂閱、零額外設定）。另一條路是設 GOOGLE_API_KEY 走 Gemini。只讀 Space 與訊息不需要 AI 供應商。

儀表板的下拉選單、CLI 的 --provider、MCP 的 provider 參數接受同一組值：claude、auto、claude_cli、gemini。

Claude Code CLI 的成本：它預設會載入自己的 system prompt、CLAUDE.md 與全部工具定義（實測一個 2-token 的 prompt 也會寫入 19,085 token 的快取）。ChatPulse 固定停用工具與 MCP、改用自己的 system prompt，實測降到接近 0。

# 目前有哪些可用
$ curl -s localhost:8000/api/v1/providers
$ ./scripts/run_summary.sh --list-providers

# 伺服器預設
$ export CHATPULSE_AI_PROVIDER=claude_cli
# 單次覆寫
$ ./scripts/run_summary.sh "示範頻道" 50 --provider gemini

// 安裝

一個指令走完引導

互動式引導，每一步都有說明，可重複執行，已完成的步驟會自動跳過。依序處理 Python 環境 → 憑證檢查 → Google 授權 → 選擇入口並安裝。

git clone https://github.com/mark22013333/ChatPulse.git
cd ChatPulse

# client_secret.json 不在版控裡，要自己放進 config/
mkdir -p config

# 完整引導（Windows：雙擊 chatpulse.bat）
./chatpulse.sh

# 裝好之後，日常只要這一行
./chatpulse.sh web      # 啟動儀表板 → http://localhost:8000
  • 不用裝 Node.js。儀表板畫面（React 19 ＋ Vite 的建置產物）已隨專案進版控；只有改前端原始碼時才需要。
  • Windows 安裝 Python 時務必勾選「Add python.exe to PATH」，而且不要把專案放在 OneDrive 同步資料夾裡（SQLite 的檔案鎖在同步資料夾或網路磁碟上會失敗）。
  • 檢查安裝狀態：./chatpulse.sh check 逐項報告 Python 環境與套件、client_secret.json、Google 授權範圍、可用的 AI 供應商、Sepia 潤稿規則與儀表板畫面，不通過的項目會印出下一步該做什麼。

子命令

  • web：啟動儀表板，日常最常用
  • check：檢查安裝狀態，不動任何東西
  • auth：重新做 Google 授權（換帳號時）
  • mcp：重新註冊 Claude Code 的 MCP 入口
  • Sepia 潤稿規則已 vendored 進 repo，不用另外安裝任何 skill 或 API key

// 資料處理邊界與已知限制

團隊共用前請先讀

前四條是 SPECIFICATION.md 第十節寫明、已經做出的決定（README 的「資料處理邊界」摘要了其中幾條），理由與代價都在那一節。

  • 沒有 Space 排除清單所有你有權讀取的 Space，對話內容都可以被送去 AI 產生摘要與草稿，包含公部門與金融客戶專案群組。這些對話會離開公司環境、送到所選的 AI 供應商；以個人 API key 呼叫時，資料處理條款與公司的 Google Workspace 合約不是同一份。
  • 摘要與草稿以明文存在本機 90 天對話全文不落地，但產生出來的摘要與草稿會以明文存在本機 SQLite 中 90 天。過期資料是在儀表板啟動時清除的，長時間不重啟就會存放得更久。
  • 訊息裡的圖片也會送給 AI截圖是無定向的畫面捕捉，可能夾帶 scrollback 裡的 token 或其他客戶名稱；模型還可能把截圖裡的憑證或個資轉寫進摘要，跟著摘要明文存 90 天。全面關閉用 CHATPULSE_IMAGES=0；只排除特定聊天室用 CHATPULSE_IMAGE_EXCLUDED_SPACES。
  • 參考專案會把原始碼片段送給 AI只限你自己登錄的 repo（不是自動掃描）。片段本身不落地，但草稿裡的程式碼會跟著草稿存 90 天。.env 之類的路徑整份跳過、片段內的金鑰會遮蔽，但那是 best-effort。全面關閉：CHATPULSE_CODE=0。
  • Gemini 免費層每天只有 20 次請求gemini-3.6-flash 免費層 2026-09-05 實測每天 20 次；這是改成可切換供應商的直接原因。
  • config/ 裡有一份明文的 Google refresh token安裝引導的 Google 授權、MCP 與 CLI 入口用的是 config/google_chat_token.json，裡面是明文的 refresh token，等於這個 Google 帳號的 Chat 讀寫授權。程式只把權限收成 0600，Windows 沒有這種權限位元、連這一步都做不到。不要複製、分享這個檔，也不要放進同步資料夾或版控。
  • 儀表板的 token 加密，金鑰預設與資料庫同目錄儀表板把 token 以本機金鑰加密存進 SQLite（從上面那個檔匯入）；金鑰檔預設是 data/token.key（0600），與資料庫同目錄但不同檔。要更嚴格可用 CHATPULSE_KEY_FILE 指到別的位置。
