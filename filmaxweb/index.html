FilmaxWeb

把放滿影片、相片與 PDF 的硬碟，變成在瀏覽器裡就能看的媒體庫。

自動刮削片名與海報、遠端連線自動降畫質、字幕即時轉檔，全部跑在自己的機器上。片庫放在你自己設定的 FTP 伺服器上（片庫與服務同機時，ffmpeg 可以直接讀本機磁碟）；資料庫是單檔 SQLite，帳號可以選配放 MSSQL。

安裝 GitHub

需求：Python 3.10+ 與 ffmpeg；僅供管理你自己合法持有的影音檔案

// 功能

影片、字幕、相片、PDF，一個網站看完

後端是單一行程的 FastAPI 服務，前端不用框架、原生 JS。掃描會遞迴列舉片庫，影片、相片與 PDF 各自進自己的分頁。

01 · 影片自動辨識片名、年份與季集

從檔名解析片名／年份／季集，一集一資料夾的影集也會併成同一個條目，再向 TMDB 抓海報與簡介。右圖的示範條目是虛構資料，中繼資料已手動修正過，所以出現「手動修正過」的提示。

  • TMDB 沒抓對的，可以「手動指定 TMDB」或「改片名／年份」；手動修正過的條目，之後自動刮削不會再蓋掉它
  • 每個檔案標出這次是「直接播放」或「轉碼播放」，並列出解析度、編碼與片長
  • 沒設 TMDB_API_KEY 時掃描會跳過 TMDB 刮削，仍可用檔名瀏覽與播放

02 · 播放器吃得下的直送原檔，吃不下的即時轉碼

mp4＋H.264＋AAC 這類瀏覽器吃得下的格式整檔直送；mkv、HEVC、AC3 等改走 HLS（即時轉碼，條件符合時改用不重新編碼的 remux，見下方「播放路徑」）。內嵌字幕即時轉成 WebVTT，開播時背景預抽整份，跳到中間也不必等。

  • 右上角標出目前的畫質級別、實際解析度與「直接串流／即時轉碼」
  • 字幕預設「自動選繁體中文」，依語言標籤與內容判斷
  • 遠端連線時改用綁碼率的轉碼（REMOTE_BITRATE_KBPS：程式預設 2800，.env.example 附的值是 8000）

03 · 相片燈箱看相片，刻意不讀 GPS

相片牆點開是 PhotoSwipe 燈箱，按 i 打開側欄看檔案資訊與 EXIF 拍攝資訊。預覽用的是 1920px 的衍生圖，原始檔案不會被修改。

  • EXIF 用白名單讀取，不讀取也不顯示 GPS 座標
  • 影片資料夾裡的封面圖（poster.jpg、與資料夾同名的圖）不會被收進相片庫
  • 支援方格（分頁）與瀑布流（往下滑自動載入）兩種檢視

用 PDF.js 的 legacy build 在頁面裡直接閱讀，支援大檔的分段讀取。文件牆用側欄樹狀導覽資料夾。

  • 上一頁／下一頁、跳頁、縮放、「符合寬度」與「符合整頁」
  • 「原檔」用瀏覽器內建的檢視器開啟

05 · 後台參數線上改，即時生效的就即時生效

後台有掃描控制、失敗清單、使用者審核、參數頁與診斷頁。設定有固定的優先序：.env > 後台資料庫 > 程式預設，沒有例外清單。

  • 每一項標出生效方式（即時生效、存檔後套用、需重啟）與目前值的來源
  • 被 .env 蓋掉的後台設定會在參數頁標出來，不會自動刪
  • 連線資訊、綁定位址、密碼這類改錯會進不來的設定，只能在 .env 改，參數頁完全不會出現

// 播放是怎麼決定的

決定權在片源本身，以及你在區網還是遠端

容器與編碼瀏覽器吃得下（mp4＋h264＋aac）就整檔直送。吃不下時，若是 h264、已經掃出 keyframe 邊界表、keyframe 間距小於分段長度，且這個檔案的上階沒有因 remux 出錯而下線，區網走上階 remux（-c:v copy，視訊位元組原封不動、只換容器）；遠端在分段可對齊時同時提供上階 remux 與下階轉碼，由播放器自己選；沒有邊界表就單階 HLS 即時轉碼。兩階 HLS 預設關閉（HLS_TWO_RUNG），要先讓邊界表掃完再開。

上階的代價是碼率就是原檔的碼率，所以遠端多半選不到它。下階綁碼率，重編首選 NVENC 硬體編碼；預設的 FFMPEG_HWACCEL=auto 會實際試編一小段，硬體不在或驅動擋掉就自動退回 libx264。.env.example 附的畫質建議值是用 VMAF 量測後定的（程式內建的預設值比較保守：CRF 21、NVENC_CQ 28、veryfast、2800 kbps），過程寫在規格書 J 章。

ffmpeg 讀檔優先走本機路徑。片庫跟服務在同一台機器時，設 LIBRARY_LOCAL_ROOTS 讓 ffmpeg 直接讀磁碟；對應不到才回到「HTTP → FastAPI → FTP → 磁碟」那條路。

FFMPEG_HWACCEL=nvenc          # 重編首選 NVENC：同碼率畫質贏 x264 veryfast 且快 1.5 倍
X264_PRESET=medium            # CPU 退路。同 CRF 下比 veryfast 多 2.1 VMAF，只多 9% 碼率
TRANSCODE_CRF=17              # CPU 編碼的畫質
NVENC_CQ=25                   # NVENC 有自己的尺，不要跟 CRF 共用一個數字
REMOTE_BITRATE_KBPS=8000      # 曲線轉折點，再往上加買不到畫質
HLS_TWO_RUNG=false            # 兩階 HLS（區網零轉碼）。要先讓邊界表掃完再開

// 登入與權限

單一密碼，或 Google 登入加管理員審核

AUTH_ENABLED=false 時沒有登入驗證：區網內任何人都有管理員權限，外部連線直接回 403。打開後可以用單一密碼，或 Google 登入（OIDC＋PKCE）；新帳號預設要等管理員審核，GOOGLE_ADMIN_EMAILS 名單裡的人第一次登入就是管理員。

資料夾可以標成「受限」，只給有授權的帳號看；沒授權的人看不到，回 404 而不是 403。

兩個容易踩的點：GOOGLE_ADMIN_EMAILS 只是一份名單，不會建立帳號，帳號是那個人第一次登入時才建立並提升為管理員，所以設好之後啟動仍會說「還沒有任何管理員帳號」，去登入一次就好。密碼登入的 token 沒有 uid，認不出是誰，一律看不到受限資料夾；要用受限目錄就得走 Google 登入。

// 安裝

五分鐘跑起來

需求：Python 3.10+ 與 ffmpeg（Windows 建議 BtbN 的 n8.1 build）。專案附的批次檔以 Windows 為主。

# 1. 建立 .venv、裝套件、裝 playwright（測試用）
安裝.bat

# 2. 編輯 .env，至少要填 FTP 連線資訊與 TMDB_API_KEY
#    （沒有 .env 的話，啟動.bat 會從 .env.example 複製一份再請你去填）

# 3. 起服務並自動開瀏覽器 → http://127.0.0.1:8080
啟動.bat

# 4. 後台 → 媒體庫 → 開始掃描
  • 最少要填的四項：FTP_HOST、FTP_USER、FTP_PASSWORD、TMDB_API_KEY（去 themoviedb.org 免費申請）。.env.example 裡每一項都有註解。
  • 片庫跟服務在同一台機器的話，在 .env 加一行 LIBRARY_LOCAL_ROOTS，值寫成「FTP 前綴＝本機資料夾」（README 的例子是把 FTP 根目錄「/」對應到 D:\1.FTP），轉碼少繞三層。
  • macOS／Linux可以用 ./start.sh：沒有 .env 時先複製一份範例並停下來讓你填，填好再執行一次，就會建立 .venv、安裝 requirements.txt 並啟動。
  • 測試：跑測試.bat 全部跑一遍，完整輸出在 test-result.txt；每一支都是獨立腳本，不需要 pytest，會自己開臨時資料庫、自己收尾；播放器的 JS 測試需要 node，沒有 node 會標 SKIP。

單機 SQLite，幾個刻意的設計

  • 單一行程、單一寫入者。SQLite 用 WAL，寫入集中在 db.py，不必處理死鎖重試。
  • 沒有外鍵。刪除只有一個進入點 purge(reason=...)，連磁碟上的海報縮圖都在裡面一起刪；孤兒數量露在後台總覽。
  • 時間點一律 epoch 整數秒，時間長度維持浮點。續播位置若取整，每次繼續看都會往前跳最多一秒。
  • 帳號可以另外放 MSSQL（選配）；刻意不做「連不上就自動退回 SQLite」，避免兩份使用者資料各說各話。

// 對外開放前的檢查清單

原本是設計在區網用的。放上公開網域前，以下 8 項都要確認

  • 密碼AUTH_PASSWORD 換成夠長的隨機字串；要分享看片就另設 VIEWER_PASSWORD。
  • Google 登入用 GOOGLE_ADMIN_EMAILS 指定第一個管理員；GOOGLE_AUTO_APPROVE 維持 false。
  • 簽章金鑰設 AUTH_SECRET，或確認 data/secret.key 存在且權限收好。
  • CookieCOOKIE_SECURE=true。
  • 代理標頭前面真的有 cloudflared／nginx 才設 TRUST_PROXY=true。
  • 綁定位址HOST=127.0.0.1，只讓同機的 cloudflared 連得到，不要開 0.0.0.0。
  • 開發模式DEV_RELOAD=false。
  • API 文件考慮關掉 /api/docs。
