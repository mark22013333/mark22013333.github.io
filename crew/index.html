CREW

整合 Notion 的 Bug 修復與功能開發工作流 plugin，Claude Code 與 Codex 共用。

用 .spec/、deterministic state 與 Human approval gate 管理 Bug 修復與功能開發的生命週期。需求、架構、UAT 由人決定；分析、規劃、實作與 review 交給模型；Git、schema、state transition、build/test、lint 交給程式驗證。

安裝 GitHub

需求：Git、Python 3、已安裝 CREW 的 Claude Code 或 Codex；Notion 流程另需 Notion

// 功能

先確認需求，再建任務；中斷了照狀態檔接著做

Bug 主流程：/bug-start → /bug-investigate → /bug-fix → /bug-close。Feature 主流程：/plan-start → /plan → /plan-build → /plan-security → /plan-verify → /plan-review → /plan-close。

01 · Intake Refinement動手前先確認「要做什麼」

/plan-start 與 /bug-start 會先把原始需求交給唯讀的 Intake Refiner 整理成短標題與描述，列出已知限制與歧義，由人明確確認後才建立任何東西。使用者不需要手動呼叫 Refiner，它不是 Slash Skill。

  • 確認前不建 Notion 頁面、不建 .spec、不初始化 state、不動 Git branch；選「取消」就零 side effect
  • 只有不回答就可能改變需求方向時才提問，最多 3 個問題
  • 確認後、寫入任何地方前，疑似 password、token、API key、private key、Cookie 的內容必須先由人提供遮蔽版本
  • Host 不能委派時，主 Agent inline 執行同一份唯讀 contract，人類確認不能省略
/plan-start — Intake 確認介面示意（依原始碼重繪）

02 · /plan-start一個指令建好 Notion、.spec 與分支

確認後，/plan-start 在 Notion 建立任務頁、建立 .spec/{slug}/（plan.md 骨架＋state.json），並可從專案設定的 PROD 分支開出 feature/{slug} 或 hotfix/{slug}。

  • 回傳前跑 S1–S7 退出驗證：Notion 欄位用讀回頁面確認、本地狀態用 script 判定，不信任 Agent 自己的記憶
  • Notion API 失敗時仍建立本地 .spec/{slug}/，之後用 /plan-sync 補建
  • 負責人用 Git 提交 email 比對 Notion 使用者自動填入，比對不到只提示、不阻擋
/plan-start — 任務已建立介面示意（依原始碼重繪）

03 · Notion 頁面每個任務頁都是同一個結構

Feature 頁面固定 5 個區塊：需求描述、技術規格、資料庫設計、程式碼清單、開發日誌。/plan-sync（中途）與 /plan-close（結案）以區塊標題為契約，把 plan.md 與 deploy.sql 寫進對應區塊。

  • 「原始需求」與「確認後任務描述」建立時寫入，之後的同步只更新它們後面的內容
  • deploy.sql 全文寫進「遷移 SQL」，是唯一的 SQL 事實來源
  • /bug-setup 可從零建立專案資料庫、任務追蹤工具、Bug 知識庫；功能設計庫由 /plan-setup 建立
Notion — 任務追蹤工具介面示意（依原始碼重繪）

04 · 斷點續跑中斷之後，下一步由狀態檔算出來

每個任務唯一的流程狀態是 .spec/{slug}/state.json，唯一寫者是 crew-state.py。/plan-next 從 state 計算下一步，中斷後不需要靠模型回憶流程進度。

  • Claude Code 的 SessionStart hook 會讀當前 repo 的 .spec/*/state.json，提示未完成工作與下一步；不修改產品檔案、不需要網路，錯誤時不阻擋 session
  • 工作做到一半中斷時，下一步會是同一個指令加 --resume，先續跑未完成的工作單元
  • /plan-next 照實轉述 script 的答案，不自行推理流程
SessionStart hook ＋ /plan-next介面示意（依原始碼重繪）

05 · Bug 流程從通報到經驗教訓，寫在同一頁

/bug-start 在 Notion 建立 Bug 條目與最小的 state.json，不建 plan.md 也不開新分支。頁面固定有問題描述、調查過程、根因分析、修復方案、驗證、經驗教訓。

  • /bug-investigate 假說驅動調查，根因確認後才能進 /bug-fix
  • /bug-fix 修復並做回歸驗證，兩者都可 --resume
  • /bug-close 不把 build／test 等 machine evidence 當成使用者接受修復；人明確接受後才結案，拒絕就回到 /bug-fix
Notion — Bug 條目介面示意（依原始碼重繪）

// Claude Code 與 Codex

同一套流程，不綁單一 AI Host

Skill 描述的是「需要什麼能力」，例如委派、平行、tool probe、詢問使用者，而不是某一家的工具名稱。Host 沒有 multi-agent、平行 delegation 或 per-worker model 選擇時，會降級成 inline／sequential 執行，不會因此破壞流程正確性。

Workflow 先選能力 profile，再由 Host adapter 對映實際模型。正式產品程式碼只有 /plan-build 與 /bug-fix 兩條流程可以修改；其他 Skill 只能修改規格、報告、state／metadata 或外部系統紀錄。

.spec/order-csv-export/
  plan.md      # 目標與範圍、驗收條件、決策紀錄、取捨與風險、指路、檢查報告摘要
  state.json   # 唯一流程狀態，只由 crew-state.py 寫入
  deploy.sql   # DB 階段才產生

# Model profile
NONE      # Git、grep、schema validation、build/test
FAST      # repository search、證據蒐集、log 摘要
STANDARD  # 一般需求分析、review、debugging
DEEP      # architecture、DB schema、security、複雜根因

// 安裝

從 marketplace 安裝兩個 plugin

bug-workflow 管 Bug、feature-workflow 管功能開發，只需要其中一個也可以只裝一個。

# Claude Code
claude plugin install notion

claude plugin marketplace add mark22013333/crew
claude plugin install bug-workflow
claude plugin install feature-workflow

# Codex
codex plugin marketplace add mark22013333/crew
codex plugin add bug-workflow@crew
codex plugin add feature-workflow@crew
codex plugin list
  • Claude Code：安裝後重啟 Claude Code，再執行 /crew-init，或依序執行 /bug-setup、/plan-setup、/project-add。
  • Codex：上述流程已用 Codex CLI 0.158.0 做過真實 marketplace add＋plugin install smoke，安裝後兩個 plugin 皆應顯示 installed, enabled。
  • 更新：執行 /crew-upgrade（--check 只檢查），完成後開新 session，避免目前 session 仍載入舊 Skill。/crew-upgrade 由 bug-workflow 提供；只裝 feature-workflow 時，改用 README 的 Host 手動更新指令。

首次設定

  • 準備專案指令：AGENTS.md 或 CLAUDE.md（Claude Code 可用 /init 建立）。兩者都存在時都可讀；有實質衝突時會把衝突列為歧義。
  • /bug-setup、/plan-setup 建立 CREW 設定，存放位置依序為 CREW_CONFIG_HOME、$XDG_CONFIG_HOME/crew、~/.config/crew。
  • /project-add 註冊專案；自訂或非標準技術棧才需要 /plan-stack。
  • 不確定環境是否完整，可跑 /crew-doctor 健診。

// 使用前請先知道

界線與限制

  • UAT 一定由人決定machine verify／review 不能自動等同人類接受，Feature 與 Bug 都要由人明確決定是否結案。
  • /plan-run 的連跑模式不是無人值守「同 session 一次審查連跑」在本對話連跑，session 結束即暫停；時限從授權簽發起算，上限 4 小時，暫停或重開 session 不會延長。
  • 連跑停在 Build Done停在 Build Done（--until arch 時停在規劃完成 completed_plan）。不自動執行正式部署、Git push／merge、Security／Verify／Review 或 Human UAT；git commit 固定不允許。
  • Review Once 只支援 Feature不支援 Bug Workflow；預設仍是逐階段人工核准的 Interactive 流程。
  • trusted-host 模式有門檻只有能提供受保護簽章端與 worker 隔離的 Host 才適用；一般 claude -p／codex exec 不符合。
  • CREW Cockpit 只在 Claude Code唯讀的任務儀表板需 Claude Code ≥ 2.1.289；Codex 核心流程仍完整支援，但沒有 Mod UI。
