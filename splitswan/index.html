SplitSwan

macOS 狀態列的 FortiGate IPsec VPN 工具：strongSwan 前端，支援 split tunnel、多閘道輪替與自動重連。

用開源的 strongSwan 連 FortiGate IPsec VPN（IKEv2、PSK＋EAP 帳密、Mode Config），可以用來取代 FortiClient。只有指定網段走 VPN，Teams、Google Meet、一般上網都走原本的網路；三台閘道自動輪替，睡眠喚醒、切換網路、通道失聯後自動接回。

下載 GitHub

需求：Apple Silicon Mac、macOS 14 以上、Homebrew（Intel Mac 不支援）

// 功能

狀態列一鍵連線，主視窗四個分頁

主視窗有「連線」「設定」「環境檢查」「關於」四個分頁。關掉視窗 App 會繼續在狀態列執行；要完全結束，從狀態列選「結束 SplitSwan」。

01 · 連線與自動輪替先試最近連得上、連得快的那台

按「連線（自動輪替）」依過去的連線紀錄排序：10 分鐘內失敗過的閘道排最後，上次成功的排第一，其餘依成功率與連線速度。連不上就換下一台。

  • 自動重連：睡眠喚醒、切換網路、通道失聯後自動接回；按「斷線」後就不會再自動連線
  • 斷線通知：非預期中斷超過 30 秒時發 macOS 通知，恢復時再通知一次；手動斷線、睡眠喚醒後 30 秒內自動接回的情況不會通知
  • 連不上時「連線」頁直接寫出原因，例如「帳號、密碼或預先共用金鑰（PSK）錯誤」「閘道沒有回應或連不到」
  • 下方「連線紀錄」可展開，顯示 strongSwan 的協商過程與 App 的動作，可拷貝給管理者
SplitSwan — 連線介面示意（依原始碼重繪）

02 · 某台主機連不上輸入網址，檢查並加入網段

多半是那台主機不在通道網段裡，流量沒有走 VPN。在「設定」頁「通道網段」卡片下方輸入主機網域、IP、主機:連接埠或整段網址，按「檢查並加入」。

  • 用系統 DNS 查出 IPv4，不在通道網段內的直接以 IP/32 加入並儲存；已連線時接著斷線重連（目前連線會中斷幾秒）
  • 重連後檢查每個 IP 的路由是否走 utun，有填連接埠會一併測試 TCP 能否連線
  • 加入的是公網 IP 時以橘色警告提醒（可能是 DNS 沒走公司端）
  • 只想看看、不想改設定時按「只檢查」；走 VPN 了還是不通，按「複製結果」傳給管理者
SplitSwan — 設定 › 通道網段介面示意（依原始碼重繪）

03 · 環境檢查與診斷報告照紅燈由上往下按「安裝」

第一次打開時 App 會開在「環境檢查」分頁，缺的元件可以一鍵安裝：strongSwan 在背景執行 brew install strongswan（約 1 分鐘）；系統元件會跳出 macOS 管理員密碼視窗。

  • 新版 App 更新了系統元件時，會顯示「需要更新」，按「更新」並輸入電腦密碼即可
  • 「產生診斷報告」約數秒後在桌面產生 SplitSwan-診斷-<時間>.txt，不會中斷連線
  • 報告不含密碼與 PSK，但含閘道位址與通道網段，只傳給管理者
SplitSwan — 環境檢查介面示意（依原始碼重繪）

// 跟 FortiClient 有什麼不同

只有公司網段走 VPN

視訊會議的改善是依架構推論：通話流量不再經過 VPN 與公司閘道。實際效果還要看各自的網路環境。

  • 哪些流量走 VPNFortiClient 是全部（上網、視訊會議都繞去公司）；SplitSwan 只有公司設定檔列出的網段。
  • Teams／Google MeetFortiClient 下視訊要先繞到公司再出去，延遲高、容易不穩；SplitSwan 直接走本機網路，不經過 VPN。
  • 多台閘道FortiClient 手動切換；SplitSwan 自動輪替。
  • 為什麼要列出網段？FortiClient 其實也不知道公司網段，而是把全部流量都送進 VPN，交給公司閘道轉出去。SplitSwan 只讓公司網段走 VPN，所以要列出網段。

// 搭配其他 VPN（1.9.2 起）

外部 VPN、公司 VPN、一般上網與區網同時可用

另一套 VPN 程式（例如客戶或機關要求的全通道 VPN）仍負責登入、驗證碼與中斷；SplitSwan 只調整 IPv4 路由，讓一般上網與區網留在原本的網路，再讓公司網段走 SplitSwan 的公司通道。目前僅支援 IPv4。

  • 先等待，再登入外部 VPN 尚未連線時，在「自動分流」頁按「開始等待 VPN 並自動分流」記下正常的上網出口與 DNS，再用原本的程式登入外部 VPN。
  • 一般上網與區網偵測到外部 VPN 的全通道後，只加入一般外網與本機網段的路由，並驗證完整覆蓋；本機網段的直連路由被外部 VPN 移除時會自動恢復。
  • 再連公司 VPN分流啟用後，從「連線」頁或狀態列連公司 VPN。有些 VPN 程式會刪除其他程式新增的路由，所以公司網段的路由由系統元件逐條建立並標記，連線期間持續驗證，消失就停止公司連線並保留外部分流。
  • 停止與復原中斷公司 VPN 時只結束通道，路由隨公司虛擬網卡一起移除，不會依目的地刪除其他程式的路由；停止分流或正常結束 App 會先停公司通道，再復原本次分流。

// 公司設定檔（管理者）

閘道與網段放在設定檔，原始碼不含任何公司位址

建議在自己已經設定好的 App 上，到「設定」頁按「匯出加密設定檔…」：內容是閘道、通道網段、預設共享金鑰（PSK），不含你個人的帳號密碼。匯出時自訂一組密碼（至少 8 個字元），檔案用 AES-256-GCM 加密，金鑰由密碼經 PBKDF2-SHA256（600,000 次）衍生；檔案被修改過就解不開。

把檔案與密碼分開傳送（例：檔案用 email、密碼用 Teams 口頭告知）。同事按「匯入設定檔…」選取檔案、輸入密碼，App 會列出閘道與網段讓他確認，按「套用」才寫入。

也可以用明文的 company.env：透過公司內部管道私下傳給同事，同事在「設定」頁按「匯入設定檔…」選取檔案，App 驗證格式後複製到 ~/.config/splitswan/company.env（權限 600）。

加密只保密，不證明來源：有人可以自己做一份 .splitswan，把閘道換成他的主機，再連同密碼騙你匯入，你的 VPN 帳號密碼就會送過去。所以匯入時 App 會列出閘道與網段要你確認；只匯入管理者親自給的檔案，並核對閘道位址。

SPLITSWAN_PRESET_NAME="我的公司"                              # 顯示在設定頁（選填）
SPLITSWAN_GATEWAYS="203.0.113.10,203.0.113.20,203.0.113.30"   # 最多 3 台，逗號分隔
SPLITSWAN_REMOTE_TS="10.0.0.0/24,198.51.100.5/32"             # 要走 VPN 的網段；單一主機寫 IP/32

// 外掛

把與 VPN 無關的小工具放進狀態列選單

打卡提醒、會議倒數、CI 狀態這類腳本可以顯示在狀態列選單裡、必要時發通知。預設關閉，到「設定」頁的「外掛」區塊開啟；關閉時不建立任何計時器、不掃描資料夾，等於沒有這個功能。

外掛放在 ~/.config/splitswan/plugins/，檔名格式同 SwiftBar（punch-reminder.1m.sh），輸出格式是 SwiftBar 的子集，另外擴充 notify=true 發通知。每次限時 10 秒，逾時只會結束外掛本身，外掛另外啟動、而且忽略 SIGTERM 的子程序可能留在背景；最多 10 個外掛，輸出當成不受信任的資料處理。

1.9.4 起，外掛可以提供原生設定視窗：分段頁籤與分組卡片、可展開的說明、狀態卡片，會登入外部網站的測試會標示「會登入」；「取消」在沒有修改時直接關閉，有未儲存修改時先確認。外掛也可以在子選單最上方放一張資訊卡片，顯示狀態、今天的時間軸、執行條件與近 10 天的圖表；只顯示資訊、沒有動作的選單列不再看起來像按鈕。卡片資料有誤時會自動退回文字列。

repo 附一個打卡提醒範例（config/plugins/punch-reminder.1m.sh.example）：可讀政府行政機關辦公日曆表判斷放假日，也可以用覆寫檔標記特休或加班。

外掛以你本人的身分執行。它能讀到你的 VPN 帳號密碼與 PSK（secrets.conf）、能透過輔助程式連線或斷線，也能存取你帳號下的所有檔案。只安裝你信任、而且看得懂內容的腳本；不要把網路上下載的腳本直接放進外掛資料夾。

標題 | settings=true card=…  # 1.9.4 起，選填
---
一般項目
有顏色的項目 | color=red
開網頁 | href=https://example.com/punch
有子選單
--子項目
---
提醒 | notify=true notify_id=reminder-1 href=https://example.com/punch

// 安裝

下載 dmg，拖進「應用程式」

先跟管理者拿兩樣東西：加密設定檔（.splitswan）與它的匯入密碼。另外準備好你自己的 VPN 帳號密碼，並安裝 Homebrew。

# App 沒有經過 Apple 公證（只有 ad-hoc 簽章），只有第一次會被擋。
# 到「系統設定 → 隱私權與安全性」按「仍要打開」，或在終端機執行：
$ xattr -dr com.apple.quarantine /Applications/SplitSwan.app
  • 下載：到 Releases 下載 SplitSwan-<版本>.dmg（不要下載 SplitSwan-Windows-… 開頭的檔案），把 SplitSwan 拖進「應用程式」資料夾。之後的一鍵更新需要 App 放在這裡。
  • 環境檢查：App 會開在「環境檢查」分頁，照紅燈由上往下逐項按「安裝」。
  • 匯入公司設定：「設定」分頁按「匯入設定檔…」，選取 .splitswan 並輸入匯入密碼。閘道、網段與 PSK 會自動帶入，請核對閘道位址後再套用。
  • 填帳號密碼：填入你自己的使用者名稱與密碼，按「儲存」。
  • 連線：先把 FortiClient 斷線（兩個同時連會衝突），回「連線」分頁按「連線（自動輪替）」。狀態列圖示變成實心盾牌就是連上了。
  • 建議順手做：「設定」頁打開「登入時自動啟動」；第一次斷線超過 30 秒時會詢問是否允許通知，請按「允許」。

之後更新

  • 1.7.0 以後：「關於」頁按「檢查更新」，有新版本時按「下載並安裝」。App 會下載、驗證發布者的數位簽章，再取代目前的 App 並重新開啟，VPN 連線不會中斷；簽章不符就不安裝。
  • 勾選「每天自動檢查更新」（預設不勾選）會每天檢查一次，有新版本時顯示在狀態列選單，但不會自動安裝。
  • 1.6.x 以前：沒有一鍵更新，請手動下載安裝一次 1.7.0 以後的版本，設定會保留。
  • 新版有更新系統元件時，「環境檢查」會顯示「需要更新」，按「更新」並輸入電腦密碼即可。

// Windows 版（beta）

托盤 App，透過 WSL2 裡的 strongSwan 連線

Windows 版是通知區域（托盤）App，背後用 WSL2 裡的 Linux strongSwan 連公司的 FortiGate，再由 Windows 路由把公司網段導進去。這是實驗版：連線引擎已在真機上測過可用，但托盤 App 的畫面還沒在 Windows 真機上完整驗證過。下載請到 Releases 找 SplitSwan-Windows-x.y.z.zip。

  • 需求x64 的 Windows 11，或 Windows 10 2004（組建 19041）以上；BIOS 已開啟虛擬化。ARM64 Windows 不支援。首次設定要能連到 GitHub（安裝 WSL）與 releases.ubuntu.com（下載 Ubuntu，約 370 MB）。必須用本身就是系統管理員的帳號登入，每次啟動都會跳 UAC 提權（要改路由與 DNS 規則）。
  • 首次設定精靈依序做系統檢查、安裝 WSL、下載並匯入 Ubuntu 24.04（約 370 MB，比對官方 SHA256）、安裝 strongSwan、VPN 設定、測試連線，不需要開終端機。
  • 與 Mac 版共用設定檔匯入同事從 Mac 版匯出的 .splitswan；閘道自動輪替的排序規則同 Mac 版。密碼與 PSK 用 Windows 帳號加密（DPAPI）。
  • 和 Mac 版的差異不會開機自動啟動、不能匯出 .splitswan、不支援 IPv6；自動重連預設關閉。只支援 WSL 預設的 NAT 網路模式，內網網段不能跟 WSL 的 NAT 網段重疊。
  • 尚未在真機驗證首次設定精靈（WSL 安裝、重開機續接、下載匯入、UAC）與桌面／開始選單捷徑還沒在 Windows 真機上實測。公司端點防護或 Hyper-V 防火牆可能擋 WSL 轉發，只能實測。
  • 一鍵更新下載後用 App 內建的公鑰驗證 Ed25519 簽章，並檢查內容與版本（防止被換成舊版），任一步失敗就還原；更新時 VPN 不會中斷。需要能寫入 exe 所在的資料夾，否則改用「前往下載」手動更新；0.1.1 以前的版本要先手動更新一次到 0.1.2。

// 安全

權限、密碼與已知的安全界線

App 本身不碰 root 權限，需要 root 的動作都集中在 root 擁有的輔助程式 /usr/local/libexec/splitswan-helper，它只接受 status、up、down、reload 等固定幾種參數，其他一律拒絕。

  • PSK 與密碼只存一個地方存在 /opt/homebrew/etc/swanctl/conf.d/secrets.conf（權限 600）；公司位址只存在 ~/.config/splitswan/company.env（權限 600），兩者都不在 repo 裡。
  • 加密設定檔取決於匯出密碼請用不容易猜到的密碼，並與檔案分開傳送。
  • 加密只保密，不證明來源惡意的 .splitswan 可能把閘道換成別人的主機。匯入時 App 會列出閘道與網段要你確認；只匯入管理者親自給的檔案，並核對閘道位址。
  • 匯入內容一律嚴格驗證閘道最多 3 台、只接受 IP／網域字元、網段逐筆檢查、拒絕 /0 與控制字元；company.env 由驗證後的值重新產生，值用單引號包住，被 shell source 時不會執行任何內容。
  • 設定頁不顯示已存的密碼欄位留空代表沿用原本的值。帳號、閘道、網段只接受固定字元；密碼與 PSK 會跳脫雙引號與反斜線。
  • 診斷報告會遮蔽密碼與 PSK先用規則把 secret、password、PSK、EAP 等欄位的值換成 ***，再把 6 個字元以上的實際密碼與 PSK 精確取代。報告檔權限 600，但含閘道位址與通道網段，只傳給管理者。
  • charon log 本機其他帳號讀得到等級固定為 1（基本控制訊息），不含金鑰；但 log 檔權限 644，本機其他帳號也能讀到連線過程與閘道位址。
  • 免密碼 sudo 只放行輔助程式輔助程式是 root 擁有，一般使用者改不了。外掛以使用者身分執行、絕不經過 sudo 或輔助程式。
  • 已知限制：Homebrew 目錄可被一般使用者寫入Homebrew 安裝的 charon、swanctl 放在一般使用者可寫入的 /opt/homebrew 底下，被替換的話仍然能透過輔助程式取得 root。/opt/homebrew/etc/strongswan.d/ 同樣可由一般使用者寫入，有心人可以改掉 filelog 路徑，讓以 root 執行的 charon 寫入任意檔案。改用每次輸入密碼也有同樣的風險，差別只在於需要使用者當下在場輸入。

// 已知問題

使用前請先知道（完整 3 條）

  • 全流量模式（0.0.0.0/0）下 DNS 失敗（未解決）連線本身正常，但 macOS 系統解析失敗、外網會全斷。strongSwan 把 DNS 加到 Wi-Fi（en0）的設定裡，FortiClient 則是綁在自己的 VPN 介面上；綁在 en0 為什麼會失敗還沒查清楚。請不要把通道網段改成 0.0.0.0/0。
  • 登入時自動啟動是否會跳視窗（待確認）App 用 Apple Event 判斷是不是登入時啟動，這對 SMAppService 註冊的登入項目是否有效還沒實測。就算跳出來，關掉視窗即可。
  • 路由沒走 VPN（已有自動處置，成因未查證）strongSwan 長時間執行後，曾觀察到 charon 把遠端網段的路由裝到 en0 而不是 utun，公司主機全部連不上。輔助程式連上後會用 route -n get 檢查，任一網段沒走 utun 就斷線、重啟 strongSwan 再連同一台，只做一次（IPv6、位址範圍、/0，以及與本機網路直接相連網段重疊的會略過）。這個自動處置需要新版系統元件。

// 解除安裝

移除 App、輔助程式與設定

如果開過「登入時自動啟動」，先在設定頁關掉，或到「系統設定 → 一般 → 登入項目」移除。
